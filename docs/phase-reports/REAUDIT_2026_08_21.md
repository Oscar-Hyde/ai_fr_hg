# CLOSED-claim re-audit — 2026-08-21

Every row previously marked closed was treated as suspect and attacked with a
test designed to fail it. This records what survived, what did not, and what
is still unprovable in this environment.

## Method

For each claim, in the priority order agreed with the reviewer — security,
permissions, API boundaries, background execution, data mutation:

1. Find the function the row actually depends on.
2. Check whether any test names it. (Frequently: none did.)
3. Write a test that runs it and asserts on observed state.
4. Break the guarantee in the source and confirm the test fails.
5. Register that break as a permanent mutation.

Step 4 is the one that matters. A test added without it is a claim, not
evidence.

## The systemic problem

Of 976 public functions, **715 are never named in any test**, including 136
with security-relevant names. Test count was never a measure of coverage.

The permission authorities were the worst of it: `get_accessible_knowledge_bases`
filters every retrieval call, `check_agent_access` and `_check_tool_access`
gate model-facing capability, and `authorized_memory_scope` is SEC-01's tenant
isolation. None of the four was named by any test. A fault in a permission
function does not raise — it silently widens access, so it looks exactly like
the feature working.

Two rows were closed citing tests that had never been written.
`TestRegisterEvidenceIsReal` now fails the build if a closed row names a code
symbol no test references — that specific lie is no longer writable.

## Harness gaps found

Eight defects in `fakebench` itself, each of which had silently prevented an
area from being tested. Three would have made a *permission* test pass
vacuously:

- `get_list` applied the row-permission hook after `pluck` projection, handing
  it a bare string — the SEC-02 bypass, reproduced inside the harness.
- `or_filters` was swallowed by `**kwargs`, so folder scoping ran unfiltered.
- `LIKE` ignored MariaDB's backslash escaping.
- `frappe.cache()` was a `None` stub, so admission control never ran.
- `get_meta` had no `.fields`; `get_permitted_fields`, `get_roles` and
  `clear_document_cache` did not exist.
- Filter comparisons were stricter than MariaDB and rejected valid code.

A verification harness that is wrong in the same direction as the code proves
nothing. These are recorded rather than quietly patched.

## What is still not proven

Nothing here rests on the runtime tier. Unproven and unclaimed: MariaDB,
transactions, InnoDB isolation, index behaviour, deadlocks, Redis as deployed,
worker execution, `bench migrate`, and browser Desk behaviour.

CHAT-09 is the standing example — a REPEATABLE READ interaction no offline
tier can reach. It stays OPEN for that reason.

`TASK-02` illustrates the boundary precisely: the tests prove the claim path
*requests* the lock and *handles losing* the race. They cannot prove two
workers will not both win it.

Cancellation is the second worked example. Committing `status = Cancelled`,
checking authority, writing the audit record and refusing terminal states are
all covered. Whether `send_stop_job_command` reaches a live worker is not —
that needs real Redis. The application already assumes it might not, which is
why the cooperative checkpoints exist and now carry their own mutations.
